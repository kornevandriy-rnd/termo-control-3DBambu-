Farm climate monitor — запуск на Raspberry Pi
==============================================

У цій папці лише те, що потрібно на Pi:
  - farm_monitor.py        (сама програма)
  - farm_config.py         (розкладка/пороги/проводка — читає config.json)
  - run_on_pi.sh           (поставити Qt і запустити одним рядком)
  - setup_hw.sh            (I2C + бібліотеки для реальних датчиків)
  - i2c_scan.py            (перевірка проводки: що на яких каналах)
  - check_config.py        (показати розкладку датчиків з config.json)
  - install_autostart.sh   (автозапуск-кіоск при ввімкненні Pi)
  - kiosk.sh               (фуллскрін-launcher, один екземпляр)
  - config.example.json    (зразок config.json: розкладка, пороги, Telegram)

КРОКИ
-----
1. Скопіюй цю папку на Raspberry Pi (напр. у /home/pi/farm-ui).

2. Відкрий Термінал НА РОБОЧОМУ СТОЛІ Pi і перейди в папку:
     cd ~/farm-ui

3. Постав Qt і запусти:
     sudo apt update
     sudo apt install -y python3-pyqt6
     python3 farm_monitor.py

   Або одним рядком:
     bash run_on_pi.sh

КЕРУВАННЯ
---------
   F11  - повний екран (або F). Esc - вийти з фуллскріну (не закриває).
          Стартує у вікні ~85% екрана.
   Вийти: Ctrl+C у терміналі, з якого запущено, або закрити вікно.

ЯКЩО ЩОСЬ НЕ ТАК
----------------
 - "could not connect to display" / "qt.qpa.plugin": запускаєш не з
   робочого столу Pi (а з консолі або по SSH). Запусти з термінала
   на самому десктопі.
 - "bash run_on_pi.sh" лається на $'\r' (Windows-переноси рядків):
     sed -i 's/\r$//' run_on_pi.sh
   і запусти ще раз. Для "python3 farm_monitor.py" це неважливо.
 - Під час apt install потрібен інтернет на Pi (одноразово).

АВТОЗАПУСК-КІОСК (Pi вмикається -> одразу дашборд на весь екран)
----------------------------------------------------------------
   cd ~/farm-ui-pi
   bash install_autostart.sh
   sudo reboot

 - Ставить автозапуск під XDG / labwc / wayfire (що є в системі);
   kiosk.sh через flock не дасть запуститись двом копіям.
 - Також вмикає вимкнення без пароля, щоб кнопка "Вимкнути" в інтерфейсі
   коректно гасила Pi (праворуч угорі на екрані огляду -> підтвердження).
 - Вимкнути автозапуск: bash install_autostart.sh --remove (потім sudo reboot)
 - Ручний фуллскрін без автозапуску: python3 farm_monitor.py --fullscreen

РЕАЛЬНІ ДАТЧИКИ (плагінити по одному, від 1 до 21)
--------------------------------------------------
 Підтримка суміші: AHT10/AHT20 (0x38), HDC1080 (0x40), BMP280/BME280 (0x76/0x77,
 тиск). Тип у кожному каналі визначається сам за I2C-адресою.
 Проводка (Pi -> TCA9548A -> датчик):
   Pi 3V3 (pin1) -> TCA VIN ; Pi GND (pin6) -> TCA GND
   Pi SDA (pin3) -> TCA SDA ; Pi SCL (pin5) -> TCA SCL
   TCA A0/A1/A2 -> GND (0x70); A0->3V3 (0x71); A1->3V3 (0x72)
   TCA канал N: SDN -> датчик SDA, SCN -> датчик SCL ; VIN->3V3, GND->GND
   Схема за замовч.: поверх 1->0x70, 2->0x71, 3->0x72 ; канал = стелаж - 1
 Кроки:
   bash setup_hw.sh                       # I2C + бібліотеки у .venv-hw
   (якщо I2C щойно увімкнено: sudo reboot)
   i2cdetect -y 1                         # має бути 0x70 (та 0x71/0x72, якщо є)
   .venv-hw/bin/python i2c_scan.py        # покаже 0x38/0x40/0x76 по каналах
   python3 check_config.py                # (опційно) перевірити розкладку
   .venv-hw/bin/python farm_monitor.py --hardware
 Очікувано: підключені датчики - живі; решта сірі (offline); чип N/21.
 Розкладку/пороги/калібрування правиш у config.json (див. config.example.json),
 код чіпати не треба.

ЖИВЛЕННЯ (вимикач / розетка)
----------------------------
 Pi вмикається сам, щойно подати живлення — окремий "power on" не потрібен.
 - Вимкнути: тап "Вимкнути" в UI -> зачекати ~10 с (екран згасне) -> рубати
   вимикач. Вранці: увімкнув вимикач -> Pi сам стартує в кіоск.
 - Вимикач краще ставити на МЕРЕЖЕВІЙ стороні (до БЖ, 230 В), не на USB-C 5 В:
   Pi 5 тягне до 5 А, дешевий 5 В вимикач дає просадку й throttling.
 - НЕ рубай живлення замість "Вимкнути" (поки ФС звичайна -> ризик для SD).
 - Згодом, коли застосунок фіналізуємо: read-only overlay FS (raspi-config ->
   Performance -> Overlay File System) -> живлення можна рубати будь-коли.

ТРИВОГИ ТА TELEGRAM (опційно)
-----------------------------
 - Тривоги видно по червоному чипу "тривоги" і червоних рамках плиток
   (тап по чипу -> список, де саме). Лог пишеться у alerts.log поряд
   із програмою.
 - Щоб слати тривоги в Telegram:
     cp config.example.json config.json
     nano config.json        # впиши token і chat_id
   Токен: @BotFather (/newbot). chat_id: @userinfobot.
   Порожній config = Telegram вимкнено. config.json нікуди не комітиться.

Без заліза застосунок сам переходить у СИМУЛЯЦІЮ (для перегляду інтерфейсу).
Демо: Стелаж 4 "гарячий" (тривога), Стелаж 6 / середній поверх - offline.
