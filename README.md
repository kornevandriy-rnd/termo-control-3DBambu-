# Farm climate monitor — UI (прототип)

Нативний десктоп-застосунок (PySide6 / Qt) для моніторингу клімату 3D-ферми.
Розрахований на Raspberry Pi 7″ Touch Display 2 (портрет 720×1280), але
запускається й на Windows для розробки.

Дані беруться з **реальних датчиків** (AHT10/AHT20, HDC1080, опційно
BMP280/BME280 для тиску) через мультиплексори TCA9548A — тип датчика в кожному
каналі визначається **автоматично** за I2C-адресою. Якщо заліза немає (напр. на
ПК для розробки), застосунок сам переходить у **симуляцію**, щоб бачити
інтерфейс. Розкладка, пороги, проводка й калібрування задаються у `config.json`
(див. `config.example.json`) — масштабування з 1 до 21 датчика **не потребує
правки коду**.

## Запуск (Windows)

```powershell
cd farm-ui
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe farm_monitor.py
```

## Запуск (Raspberry Pi OS, Bookworm/Trixie)

PySide6 не має пакета під ARM, тож на Pi використовуємо PyQt6 з apt (код сам
обере доступну бібліотеку — venv не потрібен):

```bash
sudo apt update
sudo apt install -y python3-pyqt6
cd ~/farm-ui
python3 farm_monitor.py                # віконний режим (для дебагу)
python3 farm_monitor.py --fullscreen   # одразу на весь екран
```

Або просто: `bash run_on_pi.sh` (ставить PyQt6 і запускає).

## Автозапуск-кіоск на Pi

Щоб Pi при ввімкненні одразу показував дашборд на весь екран без термінала:

```bash
cd ~/farm-ui
bash install_autostart.sh
sudo reboot
```

Скрипт ставить автозапуск одночасно під XDG / labwc / wayfire (що з них є на
твоїй системі), а `kiosk.sh` через `flock` гарантує лише один екземпляр — тож
подвійних вікон не буде. Запускається `python3 farm_monitor.py --fullscreen`.

- Вимкнути автозапуск: `bash install_autostart.sh --remove` і `sudo reboot`.
- Якщо після ребуту не стартує — напиши, який компонувальник у системі
  (`echo $XDG_CURRENT_DESKTOP`), підлаштуємо.

`install_autostart.sh` також налаштовує **вимкнення без пароля** (sudoers), щоб
кнопка «Вимкнути» працювала з кіоску. Для розробки кнопка нешкідлива: на
Windows/без sudo вона просто нічого не робить.

## Живлення: вимикач / розетка

Pi вмикається автоматично, щойно отримує живлення — окремий «power on» не
потрібен. Робочий процес:

- **Вимкнути (ввечері):** тап «Вимкнути» в UI → зачекай ~10 с, поки екран згасне
  (Pi коректно зупинився) → лише тоді рубай вимикач.
- **Увімкнути (вранці):** увімкни вимикач → Pi сам завантажиться в кіоск.

Поради:
- Став вимикач на **мережевій стороні** (до блока живлення, 230 В), а не на
  USB-C 5 В: Pi 5 тягне до 5 А, дешевий інлайн-вимикач на 5 В може дати просадку
  напруги й throttling.
- ⚠️ Поки файлова система звичайна — **не рубай живлення замість «Вимкнути»**
  (ризик пошкодити SD-картку).

### Куленепробивний варіант (коли застосунок фіналізуємо)

Увімкнути **read-only overlay FS** (`raspi-config` → Performance → Overlay File
System). Тоді живлення можна рубати будь-коли вимикачем — пошкодити SD
неможливо, а «Вимкнути» стає необов'язковою. Мінус: root read-only, тож
оновлення `farm_monitor.py` і запис `alerts.log`/`config.json` вимагають
тимчасово вимкнути overlay. Тому вмикаємо це **в кінці**, коли вже не правимо код.

## Керування

- Тап по плитці стелажа → екран з поверхами 1/2/3.
- «← Стелажі» → назад до огляду.
- `F11` (або `F`) — перемкнути повний екран; `Esc` — вийти з повного екрана
  (програму не закриває). Стартує у вікні ~85% екрана.
- Вийти: `Ctrl+C` у терміналі, з якого запущено, або закрити вікно.

## Що на екранах

- Огляд: 7 плиток-зон (стелажів) із середньою T/RH, колір рамки = статус
  (зелений / жовтий / червоний; сірий = датчик offline). Зверху 4 клікабельні
  чипи: **сер. температура** і **сер. вологість** (→ де найвища/найнижча,
  стелаж+поверх), **тривоги** (→ список де саме), **датчики N/21** (→ список
  offline). Демо: Стелаж 4 «гарячий», Стелаж 6/середній поверх — offline.
- Деталь стелажа: три картки поверхів у фізичному порядку — зверху **Верхній**,
  посередині **Середній**, знизу **Нижній** — із T, вологістю, тиском і
  міні-графіком тренду (помаранчева — температура, синя — вологість).
- Кнопка **«Вимкнути»** (праворуч угорі огляду) → підтвердження → коректне
  вимкнення Pi.

## Пороги статусів

Задаються у `config.json` → `thresholds` (дефолти:
`temp_warn/alert = 32/38 °C`, `hum_warn/alert = 55/65 %`). Без `config.json`
беруться саме ці значення.

## Датчики та масштабування (config.json)

Уся топологія й проводка — у `config.json` (скопіюй `config.example.json`).
Код не треба чіпати, коли додаєш датчики або міняєш розкладку.

- **`layout`** — `racks`, `floors`, назви поверхів, кількість колонок плиток.
- **`i2c.floor_mux`** — адреса TCA9548A на кожен поверх (дефолт `0x70/0x71/0x72`);
  канал = `номер стелажа − 1`. Тип датчика в каналі визначається сам:
  `0x38`→AHT10/AHT20, `0x40`→HDC1080, `0x76/0x77`→BMP280/BME280 (тиск).
- **`sensors`** — точкові перевизначення на позицію, якщо проводка нестандартна:
  `{"rack":3,"floor":2,"mux":"0x71","channel":5,"type":"hdc1080"}`.
  `type` можна лишити `auto`.
- **`calibration`** — зсуви на позицію: `{"4,2": {"t_offset": -0.6, "h_offset": 2}}`.
- **`logging.readings_csv`** — шлях до CSV з історією показів (порожньо = вимкнено;
  за замовчуванням вимкнено, щоб не зношувати SD / працювати на overlay FS).

Масштабування «1 → 21»: підключаєш будь-який наявний датчик у канал — він сам
стає онлайн; мультиплексор чи датчик, підключені пізніше, підхоплюються без
перезапуску. Перевір розкладку без заліза: `python3 check_config.py`.

## Сповіщення / тривоги

- Тривоги видно по червоному чипу **«тривоги»** (лічильник) і червоних рамках
  плиток; тап по чипу → список, де саме. Детекція працює у фоні з
  антидеренчанням (подія має протриматись кілька тіків, щоб не спамити).
- Кожна тривога та її відновлення пишуться у `alerts.log`.
- **Telegram** (опційно): скопіюй `config.example.json` → `config.json` і впиши
  токен бота та `chat_id`. Порожнє = вимкнено. Як отримати: `@BotFather`
  (`/newbot` → токен), `@userinfobot` (твій `chat_id`). `config.json` у git не
  потрапляє.

## Реальні датчики (`--hardware`)

Датчики читаються самі — плагінити можна по одному, від 1 до 21. На Pi:

1. Підключи датчики через TCA9548A (проводка нижче) — будь-яка суміш
   AHT10/AHT20, HDC1080, а де треба тиск — BMP280/BME280.
2. `bash setup_hw.sh` — вмикає I2C і ставить бібліотеки в `.venv-hw`
   (якщо I2C щойно увімкнено — `sudo reboot`). HDC1080 бібліотек не потребує.
3. `i2cdetect -y 1` → має бути `0x70` (і `0x71/0x72`, якщо є); потім
   `.venv-hw/bin/python i2c_scan.py` → по каналах побачиш
   `0x38(AHT10/AHT20)`, `0x40(HDC1080)`, `0x76/0x77(BMP280/BME280)`.
4. (Опційно) підправ `config.json` під свою проводку/пороги/калібрування і
   перевір розкладку: `python3 check_config.py`.
5. `.venv-hw/bin/python farm_monitor.py --hardware` → підключені датчики онлайн,
   решта сіра (offline); чип «датчики» показує `N/21`.

Тип датчика в кожному каналі визначається автоматично за I2C-адресою, тож
різнорідний парк (більшість HDC1080 + кілька AHT + пара з BMP280) працює без
налаштувань. Датчик або мультиплексор, підключені пізніше, підхоплюються без
перезапуску.

Проводка (Pi → TCA9548A → датчик):
- Pi `3V3` (pin 1) → TCA `VIN`; Pi `GND` (pin 6) → TCA `GND`
- Pi `SDA` (GPIO2, pin 3) → TCA `SDA`; Pi `SCL` (GPIO3, pin 5) → TCA `SCL`
- TCA `A0/A1/A2` → `GND` (адреса 0x70; для 0x71 — `A0→3V3`, для 0x72 — `A1→3V3`)
- TCA канал N (`SDN`/`SCN`) → датчик `SDA`/`SCL`; датчик `VIN`→3V3, `GND`→GND
- Схема за замовчуванням: поверх 1→`0x70`, 2→`0x71`, 3→`0x72`; канал = стелаж − 1.

## Архітектура джерела даних

UI бере дані з об'єкта-джерела з трьома методами:

- `reading(rack, floor) -> Reading(temperature, humidity, pressure)` або `None`,
  якщо датчик не відповів (UI сам покаже offline)
- `history(rack, floor) -> (temps, hums)` — списки для графіка (порожні, якщо offline)
- `step()` — оновити значення

Реалізації: `HardwareDataSource` (реальні датчики через TCA9548A, опитування у
фоновому потоці) і `SimulatedDataSource` (фолбек без заліза). Середні, лічильники
й тривоги UI рахує сам із `reading()`. Альтернативно можна зробити джерело, що
читає з InfluxDB (тоді UI і збір даних розв'язані), — інтерфейс не зміниться.
